qec-decoder · one-pager · Nov 2026

Can a neural network learn to fix a quantum computer's errors better than the algorithm everyone uses?

Quantum computers don't fail loudly — they fail constantly. Every few hundred operations, a qubit decoheres and the computation corrupts. The only path to useful quantum computing runs through error correction — and error correction lives or dies on a piece of software called a decoder. This project asks whether machine learning can beat the decoder everyone trusts.

The problem, plainly

A quantum error-correcting code spreads one logical qubit across many noisy physical qubits and repeatedly measures syndromes — error fingerprints. The decoder is the algorithm that reads each syndrome pattern and guesses which physical errors caused it. Guess right and the computation survives; guess wrong and the logical qubit corrupts.

Today's workhorse is minimum-weight perfect matching (MWPM) — it models errors as edges on a graph and finds the cheapest set explaining the syndrome. It's fast and near-optimal — as long as its internal picture of the noise is right. On real hardware, the noise is correlated, biased, and drifting. Google's AlphaQubit showed a neural decoder beating MWPM on real machine data for exactly this reason.

What we built

A complete decoder-benchmarking pipeline in stim + PyMatching + PyTorch: generates rotated surface-code memory experiments, samples error syndromes, and runs decoders head-to-head on identical data — plus a Spitz-style calibrator that fits MWPM's graph weights from the syndrome data itself and a biased/correlated noise injector.

What we've measured so far

Negative

Under correctly-calibrated depolarizing noise, a learned decoder (MLP 12.5%, transformer 11.9%) loses to MWPM (5.2%) — as the theory predicts. "ML beats MWPM" is not the result here.

Negative

MWPM is shockingly robust to a wrong noise model. A 4× rate miscalibration, uniform X-bias at η=100, and alternating X/Z-bias all leave its error rate essentially untouched — the oracle only gains ~2%.

Key insight

Reweighting can't help because biased noise is still edge-representable — it fits on MWPM's graph. The only room for a learned decoder is noise the graph can't represent: multi-qubit correlated faults (leakage, crosstalk, bursts). That's exactly what real hardware produces — and why AlphaQubit's advantage showed up on real Sycamore data, not synthetic noise.

So what are we solving?

The noise-model gap. Every decoder trusts a model of the noise. On real quantum computers that model is wrong — but the syndrome data itself contains the truth. We are quantifying precisely when a learned or data-calibrated decoder beats a classical one, and building the tools that make that comparison honest.

Why it matters beyond the laptop

  • Field direction: every hardware platform crossed into working QEC in 2025–26 — the bottleneck has shifted to decoding under real noise. "QEC software engineer" is now a literal job title.
  • Active ecosystem: NVIDIA ships a CNN pre-decoder + PyMatching pipeline; Riverlane's Deltakit fund pays for exactly this class of feature. Our issue Deltakit#435 proposes the calibration utility as an upstream feature.
  • The honest niche: a rigorous, open, calibrated-baseline comparison across correlated noise — the experiment nobody has cleanly published at accessible scale.
